## 실행 환경과 데이터 보존

Node.js 24 이상, 별도 npm 의존성 없음, 빌드 단계 없음. `npm start`는 `node server.mjs`입니다. 기본 서버는 로컬 `127.0.0.1:4173`에만 바인딩합니다.

```powershell

```

이미 서버가 살아 있으면 중복 실행하지 않습니다. 먼저 `http://127.0.0.1:4173/api/guests` 또는 `/guestbook/`의 응답을 확인합니다.

- 이번 실제 4173 서버는 기존 PID2648에서 **PID15132**로 최신 코드 재시작했습니다. API `total=0`, `worldHeight=1024` 보존을 확인했습니다. PID는 참고값이며 재시작이 필요하면 명령줄/포트를 다시 확인합니다.
- 최신 로그: `server-poses-final.log`, `server-poses-final-error.log`. Node의 SQLite experimental 경고만 확인했습니다. 기존 `server-handoff.log`/`server-handoff-error.log`는 이전 실행 이력입니다.
- 실제 방명록: `data/garden.sqlite` 및 WAL 관련 파일. **이 디렉터리를 보존합니다.** 마지막 조회는 실제 등록 0명입니다. 화면의 24명은 예시 하객이며 실제 등록 카운트와 분리됩니다.
- 설정: `PORT`, `GARDEN_DB`, `INVITATION_URL`, `NODE_ENV=production`. HTTPS, 영구 저장소, 공개 접속 등 인터넷 배포 작업은 아직 완료하지 않았습니다.
- 본인 수정/삭제 권한은 브라우저의 소유자 쿠키에 연결됩니다. 테스트를 이유로 사용자 쿠키나 기존 데이터를 초기화하지 않습니다.
- 실제 앱과 원본 서비스에는 테스트 메시지를 쓰거나 기존 데이터를 수정하지 않습니다. 쓰기 검증은 격리 DB와 별도 포트를 사용합니다.

이전 서버 PID24404가 대화 중단 후 종료되어 PID2648로 복구했던 이력이 있습니다. 이번에는 확인된 PID2648 종료 시 Windows `Stop-Process`의 NullReference 오류가 발생해 PID/포트를 다시 확인한 뒤 .NET `Process.Kill`/`WaitForExit`로 종료하고 PID15132를 실행했습니다. 서버가 종료되면 프로젝트의 원래 서버를 재실행합니다. 미리보기를 살리기 위해 저장 API가 없는 임시 정적 서버로 대체하지 않습니다. 프로세스를 종료할 때는 해당 PID의 경로·명령줄과 프로젝트 관련성을 먼저 확인합니다.
